Prepared 9 October 2026. This package extends v2.3.1 staging source. It is a code candidate for review, not a live deployment. See `release/WORKSPACE_V24_2026-10-08.md` for earlier behavior, migration, tests, and acceptance checks.

## Staging rollout

Back up workbook and Drive root; complete prior v2.2/v2.3 migrations; run `migrateV24(true)` from Apps Script editor, review `unmapped` and `unmapped_policies`, then run `migrateV24(false)` as active Admin. It adds relationship child folders, default task rows, and remaps known legacy task blocks without moving old files or changing approvals. Deploy Apps Script and Netlify frontend/functions as a compatible set. Test with real accounts before production promotion. Review Drive sharing separately: application access controls do not override Drive ACLs.

The four relationship folders are `Commercial Shipping`, `FSC Certification`, `Transport`, and `Geolocation`. Custom evidence is added inside a selected block. The Customer → KODA Sales Order appears in KODA only, never in Tier 1 or later supplier blocks. Existing temporary password presentation and required first-login password change remain in place.

Prompt Studio v3.0.2 identifies each authorized source document by name, document ID and Drive URL, and provides an authorized Workspace download button. DOCUMENT_REVIEW lists links for its permitted collection; PRICE_REDACTION and ENGLISH_SUBTITLE include the selected document link. The PDF bytes still must be attached to the AI session; a link alone does not give the model access. Deploy the changed Apps Script backend as well as the frontend, then generate a new prompt run.

The 2.4.4 layout moves the selected product image into the right side of the green order header. Products, Materials and Supply Chain each use the full card width; the material and relationship secondary actions sit behind their small left arrow. My Tasks displays the two groups at full width on ordinary desktop screens so row actions stay together. Edit Relationship can change an active supplier; unfiled tracker tasks and relationship folder names follow the new supplier. Existing documents or GEO linked to that relationship block supplier reassignment pending human mapping, preserving their provenance.

The 2.4.6 Products area keeps `+ Add Product` visible and makes each product row a selector. The selected product's Edit, Product Image and Remove actions are hidden inside the arrow immediately left of `+ Add Product`; the Materials arrow contains only material actions. This Product arrow remains usable before any material is created. Order cards and the Workspace header derive their complete names from all active SO Products in sequence, with the stored legacy product field used only if no active Product rows exist.

The 2.4.7 AI output panel includes externally registered `AI_OUTPUT` documents. A prompt run can still retain `AWAITING_RESULT` when its structured result was not imported, while a PDF has already been registered separately. The panel displays `PDF REGISTERED · PENDING_REVIEW` for a linked copy and offers authorized document viewing; it does not silently approve, verify, reclassify, or export the external copy. For normal processed-copy verification, use the authorized in-app registration with its required boolean validation report, then have a reviewer verify the PDF.

The 2.4.8 AI Assistant introduced order-level AI_Output/PRICE_REDACTION and AI_Output/ENGLISH_SUBTITLE folders, source restrictions, validation reports, and human verification. DOCUMENT_REVIEW asks for every stakeholder, branch and GEO country/harvest-location discrepancy.

The 2.4.9 prompt identifies the exact destination Drive folder ID and URL for each PDF and instructs an already-authorized Drive upload connector to save the finished PDF there, followed by a JSON manifest named `<prompt_run_id>_AI_OUTPUT.json` in that same folder. The manifest records the actual uploaded file ID, filename, byte size, SHA-256, order, prompt run, source document and actual validation report. A prompt cannot grant Drive permissions. If the connector cannot write to the folder, the AI must report `NOT_SAVED` and cannot claim a Sheet/Drive update. The source must remain unchanged. No browser login is required for this flow.

**View AI Results** synchronizes these folder files with `06_DOCUMENT_REGISTER`: it checks the manifest, order/run/source binding, expected folder, PDF signature/MIME, size, SHA-256 and basic report structure before recording a `PENDING_REVIEW` AI_OUTPUT with `redaction_verified = NO` (or `translation_verified = NO`). Users select and open the stored output in View AI Results. There is no upload or Register processed PDF button. A reviewer with `EVIDENCE_REVIEW` opens that same PDF, records their own checks and verifies it; the same row then becomes a verified REDACTED/EN_SUBTITLE copy eligible for the existing translation/export rules. The backend checks the full validation report, file checksum and folder again before promotion; it does not independently prove the PDF's content, so authorized human review is still mandatory. Existing external AI_OUTPUT records in older folders remain viewable but cannot be promoted through this path. Generate a new prompt after deploying Apps Script and Netlify together; persisted older prompts do not gain the new routing text.

The 2.4.10 ENGLISH_SUBTITLE prompt accepts an approved original SO/EVIDENCE or a human-verified redaction. It instructs the AI to inspect actual pages, text and scanned pixels for monetary values before translating an original. No prices: translate without asking. Unredacted prices: pause and ask the user whether to redact first. YES uses a separately persisted conditional PRICE_REDACTION prompt included with the English prompt; after its PDF is saved and human-verified, the user generates a fresh ENGLISH_SUBTITLE prompt for the redacted copy. Explicit NO permits translation of the original with its prices intact. The report must record `price_check_performed`, `monetary_values_present`, `price_redaction_decision`, and explicit confirmation and its excerpt for the NO branch; the backend rejects a priced original without the required decision. If the document cannot be inspected or the user has not decided, no translated PDF should be uploaded. The same authorized Drive-folder/manifest sync and reviewer controls apply to translations from either source. Conditional price prompts without output are hidden from View AI Results.

The 2.4.11 Export Center permits selecting 1–10 orders in one action, with Full Package or an explicit document selection for each order. It creates one ZIP and one download button per order, preserving that order's Drive `98_Export` folder and `19_EXPORT_LOG` record. Every package rechecks its order scope, document visibility, active approval and AI verification. One invalid order returns a scoped error while successful orders remain available. Export ZIP names include the run ID, so a new export of the same order no longer collides with its earlier filename. Retrying the same request key returns the existing ZIP; clicking export again creates a new version. Existing exports and source documents remain unchanged.
